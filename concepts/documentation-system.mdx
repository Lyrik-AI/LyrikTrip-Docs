AnyAgent 把**公开阅读层**和**工程真源**分开维护。

## 分层

| 层级 | 路径 | 用途 |
| --- | --- | --- |
| 公开阅读层 | `Lyrik-AI/LyrikTrip-Docs` | 面向用户的 Mintlify pages、navigation 和 publishing configuration。 |
| 项目入口 | `README.md` | 人类 quickstart 与仓库概览。 |
| 需求真源 | `requirements.md` | What / why。 |
| 任务状态 | `todo/*.md` | Progress、evidence 和 remaining work。 |
| 长期文档 | `docs/architecture`、`docs/security`、`docs/acceptance`、`docs/performance` | Stable contracts、运行说明、验收指南和设计约束。 |
| 草案与笔记 | `docs/_dev`、`docs/_notes` | 尚未毕业为稳定文档的设计草案和调研笔记。 |
| 代码真源 | `packages/anyagent/` | Runtime、SDK、protocol、storage、tools、plugins、server 和 CLI implementation。 |

## 发布规则

Mintlify 站点负责解释和导航，不复制工程真源。

如果页面需要深入细节，应明确指出源仓路径，例如 `docs/architecture/responses-api-sdk-and-server.md` 或 `docs/security/tool-policy.md`。当 contract 变化时，先更新源仓真源，再更新公开站点的阅读路径。

## Agent 维护规则

当你修改公开行为、配置、SDK 类型、wire contracts、storage records、安全策略或运行命令时：

<Steps>
  <Step title="先更新最近的工程真源">
    根据改动类型更新 `requirements.md`、`todo/*.md`、`docs/**` 或 protocol model。
  </Step>
  <Step title="再更新公开文档">
    只有当用户阅读路径需要变化时，才编辑 `Lyrik-AI/LyrikTrip-Docs`。
  </Step>
  <Step title="验证两层文档">
    源仓跑 docs checks；公开文档仓跑 Mintlify validation。
  </Step>
</Steps>

## 本地检查

源仓：

```bash
python3 scripts/docs/check.py --root .
python3 scripts/docs/check.py --root . --check-index
```

公开文档仓：

```bash
mint validate
mint broken-links --check-anchors
```
